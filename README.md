
  # 3D-магазин Сатори

  This is a code bundle for 3D-магазин Сатори. The original project is available at https://www.figma.com/design/A6ct5wcdBBUc3to4WtOiI8/3D-%D0%BC%D0%B0%D0%B3%D0%B0%D0%B7%D0%B8%D0%BD-%D0%A1%D0%B0%D1%82%D0%BE%D1%80%D0%B8.

  ## Запуск

  1. `npm i` — установить зависимости.
  2. Скопировать `.env.example` в `.env` и заполнить `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY`
     (личный кабинет ЮKassa → Настройки → API-ключи; тестовый режим включается там же переключателем).
  3. `npm run server` — поднять backend (создание платежей ЮKassa, хранение заказов), порт 3001.
  4. `npm run dev` — поднять фронтенд (Vite), порт 5173. Запросы на `/api/*` проксируются на backend.

  Оба процесса нужно держать запущенными одновременно во время разработки.

  ## Оплата (ЮKassa)

  Чекаут («Оформить заказ» / «Купить в 1 клик» в корзине) создаёт платёж через
  `server/yookassa.js` и переводит покупателя на страницу оплаты ЮKassa.
  После оплаты ЮKassa возвращает покупателя на сайт с `?orderId=...`,
  фронтенд опрашивает `/api/orders/:id/status`, который сверяется с ЮKassa
  и обновляет статус заказа.

  Заказы хранятся в `server/data/orders.json` (простое файловое хранилище,
  достаточное для небольшого магазина; при росте нагрузки стоит перейти на БД).

  Если ключи ЮKassa не заданы в `.env`, при попытке оформить заказ покажется
  понятная ошибка вместо оплаты — остальной сайт при этом работает как обычно.

  ## Доставка

  В форме оформления заказа есть выбор способа доставки (`DELIVERY_METHODS`
  в `src/app/App.tsx`): «СДЭК / Почта России», «Ozon Доставка», «Самовывоз
  (Москва)». Выбранный способ попадает в заказ и виден в админке в столбце
  «Доставка» — сейчас это просто пометка для ручной обработки, без реальной
  интеграции с логистикой.

  **Ozon Доставка** — реальный сервис Ozon для доставки заказов с собственного
  сайта их логистикой (не через маркетплейс). Чтобы подключить API:
  1. В личном кабинете продавца (seller.ozon.ru) подать заявку:
     «Товары» → «Приложения» → «Ozon Доставка» (рассмотрение до 5 рабочих дней).
  2. После одобрения — создать частное приложение и получить OAuth-ключи
     (Client-Id / Api-Key).
  3. Прислать эти ключи — добавлю `server/ozon.js` по аналогии с
     `server/yookassa.js` (расчёт стоимости, создание отправления, статус).

  До этого момента интеграция технически невозможна — Ozon не даёт доступ
  к API без одобренной заявки.

  ## Админка

  Панель управления доступна на `/admin` (например, http://localhost:5173/admin) —
  отдельно от основного сайта, без ссылки в обычной навигации. Пароль задаётся
  в `.env` через `ADMIN_PASSWORD`.

  В админке можно:
  - добавлять, редактировать и удалять товары (хранятся в `server/data/products.json`,
    их же читает витрина через `GET /api/products`);
  - смотреть список заказов и менять их статус выполнения (Новый / В работе /
    Отправлен / Выполнен / Отменён) — отдельно от статуса оплаты, который
    приходит от ЮKassa.

  Вход выдаёт токен, который хранится в браузере (localStorage) и живёт до
  перезапуска backend-сервера (токены сбрасываются при рестарте — это ок для
  одного владельца, при необходимости более стойкой сессии скажите, доработаю).

  ### Фото товаров

  В форме товара можно загрузить фото прямо с компьютера (кнопка «Загрузить
  с компьютера» / «Добавить фото с компьютера») — файл уходит на backend
  (`POST /api/admin/upload`), сохраняется в `server/uploads/` и отдаётся по
  адресу `/uploads/<файл>`. Поле URL остаётся доступным для ручной вставки
  ссылки, если фото уже где-то выложено. Ограничение — 10 МБ, форматы JPEG/
  PNG/WEBP/GIF.

  `server/uploads/` не попадает в git (см. `.gitignore`) — при переносе на
  другой сервер файлы нужно скопировать отдельно или загрузить товары заново.

  ## Контакты

  Реальные контакты (Telegram, Instagram, email, телефон) заданы константами
  в начале `src/app/App.tsx` — искать `TELEGRAM_HANDLE`, `INSTAGRAM_HANDLE`,
  `EMAIL`, `PHONE`.

  ## Публикация в интернет

  Сейчас проект настроен только для локального запуска. Для публикации
  понадобится: (1) захостить фронтенд (например, Vercel/Netlify), (2) захостить
  backend отдельно (Render/Railway/VPS — Vercel/Netlify не подходят для
  долгоживущего Express-процесса с файловым хранилищем), (3) прописать
  `FRONTEND_URL` в `.env` backend'а на реальный домен и обновить прокси/`fetch`
  на фронте (включая `/uploads`), чтобы они ходили на публичный адрес backend'а,
  (4) в личном кабинете ЮKassa указать боевые ключи и адрес вебхука
  `https://<ваш-backend>/api/yookassa/webhook`.
