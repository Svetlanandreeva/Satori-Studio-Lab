# SATORI HOME → единая Satori CRM

Второй бренд использует **ту же CRM и таблицы клиентов/сделок**, что Satori Studio. Сам сайт HOME — отдельный публичный интерфейс с технической очередью доставки событий, **не вторая CRM**.

## Новые части CRM
- `/api/integrations/home-orders`: HTTPS POST; подписанный HMAC-SHA256, время запроса не старше 5 минут.
- `lib/home-orders.ts`: ищет контакт по телефону или email, создаёт отдельную сделку на **каждый** новый HOME-заказ, задачу и заметку, сохраняет вложения к карточке клиента.
- `/deals`: фильтр «Оба бренда / Satori Studio / Satori Home» и бейдж HOME. Контакты общие. Домашние заказы не объединяются со сделками студии по совпавшему контакту.
- Отдельная цена в новой сделке равна 0 (рассчитывается менеджером позже); не обозначать как выручку.

## Необходимая конфигурация
1. Запустите код CRM из этой ветки после ревью, тестов и стандартного бэкапа. Выполнение deployment workflow меняет живую CRM, поэтому не сливайте без проверки.
2. Создайте секрет командой `openssl rand -hex 32`.
3. На VPS CRM создайте от имени root файл `/etc/satori-home-crm.env` со строкой `SATORI_HOME_WEBHOOK_SECRET=<64 hex symbols>`, права `chmod 600 /etc/satori-home-crm.env`. Workflow добавляет `EnvironmentFile=-/etc/satori-home-crm.env` в systemd-службу CRM.
4. На сервере сайта SATORI HOME задайте ТОТ ЖЕ секрет `SATORI_HOME_WEBHOOK_SECRET` и `SATORI_CRM_HOME_URL=https://crm.satorilabural.online/api/integrations/home-orders`; храните секрет только на сервере. Не вызывайте webhook из браузера и не помещайте ключ в код клиента.
5. Включите HTTPS, продумайте хранение PII в очереди, сроки удаления и согласие на обработку. Снаружи API открыто только для корректно подписанных запросов.
6. Отправьте тестовую заявку, подтвердите: контакт найден/создан, сделка HOME появляется в единой CRM, вложения доступны в документах клиента, повторная отправка с тем же ID не создаёт дубль, новый HOME-заказ от существующего клиента создаёт отдельную сделку.

## Ограничения MVP
- Пока нет публичного отслеживания заказа и автоматического переноса обновлений статусов обратно на HOME.
- Общая CRM показывает бренды по маркеру сделки в заметках; детальную раздельную финансовую аналитику по брендам нужно развивать отдельно.
- Каталог и цены 1688/Taobao автоматически не подключены.
- Обновление подготовлено в ветке для ревью и не опубликовано на рабочем сервере.

## Контракт
POST `/api/integrations/home-orders`:
- `x-satori-home-timestamp`: UNIX-время в миллисекундах;
- `x-satori-home-signature`: `sha256=` + hex HMAC-SHA256(secret, timestamp + "." + body);
- JSON: `{id:"SH-YYYYMMDD-XXXXXX",createdAt,type,client:{name,contact,city,email},items:[{name,quantity,link}],comment,files:[{name,type,data:base64}]}`.
Сервер проверяет подпись, время и данные заявки. Повторной отправке одного ID соответствует та же CRM-сделка.
